# 売れるアプリ ルール（LP・サインアップ・価格訴求）

> 目的: 商用リリース前後、LP/signup/ダッシュボードの変更時に「売上に悪影響を与えない」ための不変ルール。
> 参照タイミング: LP コンポーネント変更時、サインアップ/オンボーディング変更時、価格・プラン定義変更時、ブログ記事の公開時。

---

## 最重要: 課金モデル表記の整合性（景表法リスク）

**現状の課金モデル**（`src/lib/plan.ts` を唯一の真実とする）:
- **おためしプラン**: ずっと無料。顧客50人・カルテ100件などのソフトリミットあり
- **スタンダード**: 月額2,980円。全機能使い放題

**絶対に使ってはいけない表現**:
- 「30日間無料」「無料トライアル」「トライアル期間終了後に課金」
- 「期間限定で無料」「お試し期間」
- 「クレジットカード登録で無料スタート」

**正しい表現**:
- 「無料で始める」「無料のおためしプランで始める」
- 「必要になったら月額2,980円にアップグレード」
- 「クレジットカード不要 / いつでも解約OK」

### チェック箇所
LP・signup・ブログ・FAQ・特商法・規約の全文に対し、以下を grep して該当があれば修正する:
```bash
grep -rn "30日間無料\|トライアル\|期間終了後" src/ content/ 2>/dev/null
```

## サインアップ摩擦の最小化

**必須条件**:
- フォーム送信まで 30秒以内で完了できること
- 必須項目は email + password の2つのみ
- 同意系は「サインアップをもって〜に同意したとみなす」方式に統合（個別チェックボックスは避ける）
- 進捗感の可視化（ステップバー or 所要時間表示）
- ブラウザバックしてもフォーム内容が保持される

**禁止**:
- サインアップ画面でのサロン情報収集（setup で分離）
- 全項目必須のフォーム（任意項目は setup で）
- 規約3点の個別チェックボックス
- ファネル計測を欠いた変更

### 計測必須イベント（GA4）
- `sign_up_form_submit` — フォーム送信（成功・失敗を問わず）
- `sign_up_completed` — サーバー側確定（メール送信まで）
- `email_confirmed` — 確認メールリンク踏破
- `onboarding_complete` — setup 完了
- `first_record` — 初カルテ保存（アクティベーション指標）

## 社会的証明の必須配置

**LP上に最低限含めるべき要素**:
1. テスター声の直接引用（最低1件、理想は3件）
2. 累計利用数値（カルテ件数・予約件数など、小さくても可）
3. 開発者の顔・名前（`/about` ページ or LP フッター）

**更新方針**:
- `.claude/rules/blog-content.md` の一次情報エピソード集に追加があった場合、LP のテスター声セクションも更新する
- 「●●サロン様」の肩書きは許可を取ってから掲載

## CTA の一貫性

**主要CTA（全ページ共通）**:
- 文言: 「無料ではじめる」or 「無料で始める」
- リンク先: `/signup`
- 色・形: `bg-accent hover:bg-accent-light text-white font-bold rounded-2xl px-8 py-4 text-lg`
- マイクロコピー: 「初期費用0円 / クレジットカード不要 / いつでも解約OK」

**副次CTA**:
- 文言: 「料金を見る」「機能を見る」
- リンク先: 同一ページ内アンカー（`#pricing` / `#features`）

**禁止**:
- LP内に `/signup` 以外の決済関連リンクを混ぜる
- CTA文言の気まぐれな変更（A/Bテスト以外）

---

## ブログ → LP → signup のファネル整合性

- ブログ記事の末尾CTAは`/signup` または LP の `#pricing` アンカーのいずれか
- ブログ内の price 表記は `src/lib/plan.ts` と一致
- LP に無い訴求をブログで強くしない（LP で回収できないと離脱する）

---

## 運営者の顔が見える

- `/tokusho` ページに最低限「事業者名」（実名可）を開示
- LP フッターに運営者名 or `/about` へのリンク
- ブログ記事は「salon-karte編集部」単独ではなく、開発者の実名を併記

## 変更時チェックリスト

LP・signup・ブログ・価格関連を変更する際、コミット前に以下を確認する。

- [ ] 「30日間無料」等の禁止表現が新規に紛れ込んでいないか（grep）
- [ ] CTA文言・リンク先が統一されているか
- [ ] GA4 イベント計測が欠落していないか
- [ ] 375px モバイルで崩れないか
- [ ] 変更内容が `src/lib/plan.ts` と整合するか
- [ ] テスター声・一次情報が含まれる場合、`.claude/rules/blog-content.md` のエピソード集と整合するか
