# ブログ記事 制作ポリシー

> 更新日: 2026-03-09
> 目的: SEO流入を最大化し、サインアップにつなげるブログ記事の品質基準

---

## 1. 読者ペルソナ（絶対忘れない）

**読者 = 個人サロンオーナー（30〜50代女性、1人経営、スマホメイン）**

- ITリテラシー: 低い（「SaaS」「クラウド」は通じない）
- 悩み: 紙カルテの限界、ホットペッパーの費用、確定申告の不安、リピーター管理
- 検索シーン: 営業後の夜、スマホでGoogle検索
- 意思決定: 「同業オーナーの声」「実際の画面」「料金の明確さ」が決め手

**禁止用語 → 置き換え表**

| 禁止 | 置き換え |
|------|---------|
| SaaS | アプリ / サービス |
| クラウド | ネットで管理 / スマホで見れる |
| UI/UX | 使いやすさ / 操作のしやすさ |
| データベース | 顧客情報 / 記録 |
| API連携 | 〇〇とつながる |
| マイグレーション | （使わない） |
| リテンション | リピート率 / 再来店率 |

## 2. SEO設計ルール

### キーワード戦略（ボトムファネル優先）

記事を書く前に必ず以下を決定する:

1. **メインKW**: タイトルとH1に必ず含める（例: 「個人サロン 顧客管理 アプリ」）
2. **サブKW**: H2見出しに自然に含める（例: 「カルテ管理」「LINE連携」）
3. **検索意図**: このKWで検索する人は何を解決したいのか？

### ファネル別の書き方

| ファネル | 読者の状態 | 記事の目的 | CTA強度 |
|---------|----------|----------|--------|
| ボトム | ツールを比較検討中 | salon-karteを選択肢に入れてもらう | 強（複数CTA） |
| ミドル | 課題は認識、解決策を探し中 | 課題解決ノウハウ + salon-karte紹介 | 中（末尾CTA） |
| トップ | 潜在的な悩み段階 | 有益情報の提供で認知 | 弱（さりげなく） |

### 構造化データ（自動実装済み）
- BlogPosting JSON-LD: slug, title, publishedAt, updatedAt から自動生成
- BreadcrumbList: トップ → ブログ → 記事タイトル
- sitemap.ts: 記事追加時に自動反映（priority 0.7）

## 4. 一次情報ルール（最重要 — AI記事との差別化）

### なぜ一次情報が最重要か
- 2026年: 新規Webページの74.2%にAI生成コンテンツが含まれる
- Googleは E-E-A-T（Experience = 経験）を最重視
- **テスターの実体験 + 開発で得た業務知識 = AIには書けない唯一の差別化要因**

### 一次情報の種類と記事への入れ方

| 種類 | 例 | 記事での表現 |
|------|---|------------|
| テスターの声（直接引用） | 「freeeで確定申告準備してるけど…」 | `> 「引用」` ブロック |
| テスターの運用実態 | HPからWeb予約に切り替え中 | 地の文で「実際のオーナーさんは…」 |
| 開発で気づいた業務知識 | 回数券の前受金計上問題 | :::warning や :::point で囲む |
| 具体的な数字 | 「施術後3分で記録」「月2,980円」 | 見出しや太字で強調 |
| 正直な限界の告白 | 「確定申告が完結するわけではない」 | 「正直にお伝えすると…」の形式 |

### 一次情報の収集方法
1. テスターとの会話で出たエピソードをメモ → 記事用に整形
2. 開発中に発見したサロン業務の「意外な実態」を記録
3. **記事を書く前に、必ずオーナー（ユーザー）に質問して新しいエピソードを収集する**
4. 「許可を取って」引用すること（匿名でもOK）

### 一次情報チェック（公開前必須）
- [ ] テスターの声（直接引用）が最低2箇所ある
- [ ] 開発者としての業務知識が最低1箇所ある
- [ ] 正直な限界（salon-karteでできないこと）が最低1箇所ある
- [ ] 具体的な数字（金額、時間、回数）が3つ以上ある

## 5. 競合名の使用ルール

### 基本方針: 使ってよい。ただし公平に。

比較記事で競合サービス名（ホットペッパー、STORES予約、Airリザーブ等）を
記載することは、SEO上必須かつ法的にも問題ない。

### 守るべきルール

| ルール | 理由 |
|--------|------|
| 公開情報のみ使う | 非公開の料金・内部情報は使わない |
| 事実ベースで書く | 「高い」ではなく「月額○○円」と数字で示す |
| 競合の強みも認める | 例: 「ホットペッパーの圧倒的な集客力は個人サロンにも魅力」 |
| 「向き不向き」で表現 | 「ダメ」「使えない」等の主観的否定は禁止 |
| salon-karteの弱みも書く | 例: 「集客力はホットペッパーに及ばない」 |
| 最新情報を確認 | 料金改定・機能追加があり得るため、公式サイトで確認してから書く |

### 比較表テンプレート

```markdown
| 項目 | salon-karte | ○○（競合） |
|------|------------|-----------|
| 月額料金 | 2,980円 | ○○円〜 |
| 向いているサロン | 1人経営の個人サロン | ○○規模のサロン |
| 強み | カルテ・予約・売上が一体 | ○○ |
| 弱み | 集客力はない | ○○ |
```

**重要**: 比較記事の目的は「salon-karteが最高」と主張することではなく、
「読者が自分に合ったツールを選べるようにする」こと。
この姿勢が信頼性（E-E-A-T の T = Trustworthiness）を高める。

## 7. 品質チェックリスト（公開前必須）

### SEO
- [ ] タイトルにメインKWが含まれている
- [ ] H2/H3がKWと検索意図に沿っている
- [ ] メタディスクリプション（description）が120字以内
- [ ] slug がKWベースの英語（ハイフン区切り）
- [ ] 結論ファーストで書かれている（AI検索対応）

### 一次情報（上記セクション4のチェック）
- [ ] テスターの声が2箇所以上
- [ ] 開発者の業務知識が1箇所以上
- [ ] 正直な限界が1箇所以上
- [ ] 具体的数字が3つ以上

### コンテンツ
- [ ] 禁止用語（SaaS, クラウド等）を使っていない
- [ ] 全文が「サロンオーナー目線」で書かれている
- [ ] 1文が60字以内（スマホで読みやすい長さ）
- [ ] 太字の使いすぎがない（1セクション2-3箇所まで）

### CTA・導線
- [ ] 記事末尾にCTAがある
- [ ] ボトムファネル記事は中間CTAもある
- [ ] 内部リンク（他の記事 or LP）が2つ以上
- [ ] 関連記事の案内が末尾にある

### 技術
- [ ] frontmatter が正しいフォーマット
- [ ] category が定義済みの値（salon-management / tax-accounting / marketing）
- [ ] OGP画像が生成される（title + emoji）
- [ ] モバイル（375px）で読みやすいこと

### 競合記事（該当する場合）
- [ ] 競合の料金が公式サイトの最新情報と一致
- [ ] 競合の強みが1つ以上書かれている
- [ ] salon-karteの弱みが1つ以上書かれている
- [ ] 「向き不向き」の表現で書かれている（否定的表現なし）

## 8. 記事制作フロー

1. **KW決定**: メインKW + サブKW + 検索意図を明確にする
2. **一次情報収集**: オーナーに質問してエピソードを収集する（★最重要）
3. **競合調査**: 同じKWで上位10記事を確認し、差別化ポイントを決める
4. **構成作成**: テンプレートに沿ってH2/H3の骨組みを作る
5. **執筆**: 結論ファースト + 一次情報を散りばめる
6. **チェック**: 品質チェックリスト全項目を確認
7. **公開**: frontmatter設定 → content/blog/ に配置 → コミット

## 9. 既存記事の改善予定

既存2記事（カルテ管理 + 確定申告）に対する改善点:

| 改善項目 | 現状 | 目標 |
|---------|------|------|
| 中間CTA | なし | 記事中盤に1箇所追加 |
| 内部リンク | 各1本 | 各2本以上 |
| 具体的数字 | 少ない | 各記事5つ以上 |
| テスターの声 | あるが抽象的 | より具体的なエピソードに差し替え |
| 正直な限界 | 確定申告記事のみ | カルテ管理記事にも追加 |

→ 新記事制作と並行して、既存記事もリライトする

## 10. 一次情報エピソード集（2026-03-09 収集）

記事執筆時にここから引用する。新しいエピソードが得られたら随時追記する。

### テスターの運用実態

| エピソード | 記事での活用先 | 引用形式 |
|-----------|-------------|---------|
| Excelで正規化されていない「メモ書き」状態で顧客管理していた | カルテ管理記事、比較記事 | 地の文「実際のオーナーさんは…」 |
| ホットペッパーを使っているが費用が高い。でも集客力があるので離脱できない | ホットペッパー比較記事（核心エピソード） | `> 引用` ブロック |
| HPがなかったため、HP作成 + salon-karteのWeb予約機能を埋め込みで一元管理に移行中 | 比較記事、カルテ管理記事 | 地の文「実際のオーナーさんは…」 |
| salon-karteへの不満: ホットペッパーとの連携ができたらいい | 全記事（正直な限界として） | 「正直にお伝えすると…」形式 |
| カウンセリングシートに画像を含む緻密な情報をヒアリングしていた（気合が入っている） | カルテ管理記事、電子カルテ比較記事 | `> 引用` + 開発者コメント |
| 既存顧客を非常に大切にしている。新規はホットペッパー依存が強い | 比較記事、リピーター記事 | 地の文 |
| できるだけ無料で済ませたいというコスト意識が強い | 比較記事（価格訴求の根拠） | 地の文 |

### 開発で得た業務知識

| 知見 | 記事での活用先 | 引用形式 |
|------|-------------|---------|
| 回数券の運用が想像以上に複雑（販売・消化・残数管理・有効期限・前受金計上） | カルテ管理記事、確定申告記事 | :::point で囲む |
| データ移行が思ったより大変。既存Excel→アプリの移行は競合も苦労しているはず | 比較記事（移行コストの観点） | :::warning で囲む |
| 個人サロンは「メモのような管理」がデフォルト。正規化されたDBとは程遠い | 全記事（課題提起で使える） | 地の文 |
| カウンセリングシートのカスタマイズ性が重要（オーナーごとに質問項目がまったく違う） | 電子カルテ比較記事 | :::point で囲む |

### salon-karte のユニーク機能（競合比較で使用）

| 機能 | 差別化ポイント | 想定する比較対象 |
|------|-------------|---------------|
| 誕生日のお客様をダッシュボードに表示 | 既存顧客を大切にするオーナーの業務フローに合致 | 大手ツールにはない気遣い機能 |
| カウンセリングシートの完全カスタマイズ（質問・注意事項・同意書） | テンプレート固定の競合との差別化 | STORES予約、Airリザーブ |
| カウンセリングシートをURL + QRコードで共有 | 来店前に事前回答 → 施術時間を最大化 | 紙のカウンセリングシート |
| カルテ作成時に回数券の販売・消化が同時にできる（画面遷移なし） | 業務フローに沿った一体型設計 | 回数券が別画面の競合 |
| 物販の在庫管理が施術カルテと同じアプリ内 | カルテ + 在庫 + 売上の一元管理 | カルテ特化型の競合 |
| Web予約ページを自サイトに埋め込み可能 | HP + 予約 + カルテが一つに → ホットペッパー依存軽減 | ホットペッパー |
| 月額2,980円で全機能使い放題（顧客数・予約数上限なし） | 個人サロンのコスト意識に合致 | 機能別課金の競合 |

### salon-karte の正直な限界（信頼性のために記事に必ず書く）

| 限界 | 記事での書き方 |
|------|-------------|
| ホットペッパーとの連携はできない | 「ホットペッパーのデータを自動で取り込む機能はまだありません」 |
| 集客力はない（予約管理・顧客管理ツールであり、集客プラットフォームではない） | 「salon-karteは集客ツールではありません。既存のお客様を大切にするためのツールです」 |
| 確定申告が完結するわけではない（freee等との併用が前提） | 「確定申告そのものはfreee等の会計ソフトが必要です」 |
| データ移行は手作業が必要（Excel一括インポート機能は未実装） | 「新しいお客様から少しずつ入力していく方法がおすすめです」 |

### 価格設定の根拠

- 競合調査に基づいて月額2,980円に設定
- ホットペッパーの月額掲載料（最安でも月2.5万円〜）と比較して約1/10
- 個人サロンの月間固定費を圧迫しない価格帯
- 全機能使い放題（顧客数・予約数の上限なし）で追加課金なし
