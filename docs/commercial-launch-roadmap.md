## Phase B: 商用化ブロッカー修正（開発）

> 工数: 4-5日
> 前提: Phase A 完了後

### B-1: 機能ゲート適用（2-3日）

`src/lib/plan.ts` の定義は実装済み。各ページに制限チェックを適用する。

| ゲート | 対象ページ | チェック内容 |
|--------|----------|------------|
| 顧客数上限 | `/customers/new` | Free: 10件まで |
| カルテ数上限 | `/records/new` | Free: 1顧客あたり5件まで |
| 予約数上限 | `/appointments/new` | Free: 月20件まで |
| 写真機能 | カルテ写真アップロード | Free: 利用不可 |
| LINE連携 | `/settings/line` | Free: 利用不可 |
| カウンセリング | `/settings/counseling-template` | Free: 利用不可 |
| 売上分析 | `/sales/analytics` | Free: 当月のみ |

実装方針:
- Server Component: `getAuthAndSalon()` で `plan_type` を取得 → props 経由で制限情報を渡す
- Client Component: `<FeatureGate>` ラッパーで制限超過時にアップグレード案内を表示
- API: POST/INSERT 時にも DB 側でカウントチェック

### B-2: 404 ページ（0.5日）

`src/app/not-found.tsx` が未作成。Next.js デフォルトの404が表示される。

### B-3: Rate Limiting（1日）

現在 API エンドポイントに Rate Limiting がない。

対象:
- `/api/stripe/checkout` — 決済セッション生成
- `/api/booking/*/submit` — 予約送信
- `/api/line/*` — LINE API呼び出し
- `/api/counseling/create` — カウンセリング作成

実装方針:
- Vercel の `@vercel/edge` の Rate Limiting、または Upstash Redis ベース
- IP ベース + salon_id ベースのダブルチェック

### B-4: Cookie 同意バナー（0.5日）

GA4 使用のため Cookie 同意が必要（改正個人情報保護法 2022年4月施行）。

実装:
- LP のみに表示（ダッシュボードはログイン済みユーザーのみなので不要）
- 「同意する」クリックまで GA4 スクリプトを読み込まない
- localStorage で同意状態を保持

### B-5: LINE プラン制限の説明UI（0.5日）

LINE設定画面（`/settings/line`）にサロンオーナー向けの制限説明を追加。

実装:
- 月200通の無料枠の注意書き表示
- Push API 429エラーのハンドリング（上限超過時のユーザー向けメッセージ）
- 有料プラン（ライトプラン: 月5,000通/5,000円）へのアップグレード案内リンク

### B-6: プライバシーポリシーへの GA4/Cookie 記載（0.5日）

`/privacy` ページにGA4によるアクセス解析とCookie使用の記載を追加。

### B-7: 新規登録時 plan_type = free（0.5日）

`/setup` ページでサロン作成時に `plan_type: 'free'` を明示設定。
現在は DB デフォルト値（'free'）に依存しているが、明示的に設定すべき。
