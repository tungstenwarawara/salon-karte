## リリース判断の基本方針

**商用リリースのトリガーは「プロダクトの準備完了」ではなく「需要の確認」。**

- 見込み客が1社しかいない状態で月$45の固定費を発生させない
- Stripeゲートはテスターの検証を妨げるので、需要確認前には入れない
- テスターのフィードバックは需要検証と並行して随時対応する

## Phase 1 集中検証ウィンドウ（2026-04-24〜2026-05-08、2週間）

> 目的: 需要の有無を2週間で判定する。受動的なSEO待ちから能動的な直接ピッチに切り替える。

### 背景
- 2026-03-08 に Phase 1 開始から 6週間、有料確定は 1サロンのみ
- これまで「作る」「書く」（LP/ブログ/機能）に時間が使われ、「売る」が実行されていなかった
- 「売れない」ではなく「売っていない」状態。検証せずに撤退するとパターン化するため、2週間の集中期間で白黒つける

### 決定事項（撤回不可ライン）

| 項目 | 決定 | 根拠 |
|------|------|------|
| ターゲット | Segment B（紙/Excel管理から脱却したいベテラン個人オーナー） | ホットペッパー集客力の代替は現状不可能（Segment A 除外）。Segment B はリピート顧客管理が課題と合致 |
| 主軸チャネル | テスターさん経由の直接紹介 | 既存信頼の活用、オーナー本人が営業する心理的負担を最小化 |
| 副軸チャネル | Instagram DM（許諾ベースのソフトアプローチ） | 本業がある中で直接訪問は非現実的 |
| 禁止行動 | 新機能開発、ブログ新規執筆、LPの大幅改修 | 作る逃げに戻らないため |
| 許可行動 | 営業前のクリーンアップ（ゴースト機能除去・景表法リスク修正） | 営業資料の信頼性確保に必須 |
| 固定費コミット | Vercel Pro 有効化（$20/月）・Stripe本番化申請 | 退路を断つ |
| Supabase | Free 据え置き | 現状 226MB / 1GB、1サロンの日次アクセスで自動停止回避。500MB or 2サロン目契約で Pro 移行 |

### 判定基準

| 2週間後の有料化件数 | 判定 | 次のアクション |
|--------------------|------|--------------|
| 0件 | マーケット or 売り方の不適合 | 撤退の妥当性あり（学習として意味あり） |
| 1-2件 | 売り方は機能、スケール課題 | セグメント深掘り or ホットペッパー連携検討 |
| 3件+ | 需要確認完了 | Phase 2（商用リリース準備）着手 |

### 判断根拠の履歴

- 2026-04-24: 撤退より先に集中検証を選択。根拠: 過去プロジェクトで「検証せず撤退」のパターンが繰り返されており、パターンを断ち切る必要がある
- 2026-04-24: 全体レビュー（security / sellability / ux / ゴースト機能）を実施し、営業前のクリーンアップ項目を洗い出し。紹介特典「1ヶ月無料」が UI のみで Stripe 実装されていない問題を発見 → 準備中UIに一時安全化
- 2026-04-24: plan.ts の free 制限値を sellability.md と整合化（maxCustomers 10→50、maxRecordsPerCustomer 5件→maxRecords 100件、予約月20→30）
- 2026-04-24: 景表法リスク（「30日間無料」表記）をサインアップ1箇所・ブログ4箇所で修正
- 2026-04-24: LP pricing に未実装の「+500円写真容量アップ」オプション表記があり削除
- 2026-04-24: 開業届は本業があっても住民税普通徴収で会社バレ回避可能と判断し、提出方向で決定

### このウィンドウ中は書かないこと
- タスクチェックリスト（git commit log と SessionStart hook の実測に任せる）
- 進捗率（陳腐化するため）
- 「〇〇してから〇〇する」の順序だけ決める記述
