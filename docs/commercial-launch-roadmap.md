## リリース判断の基本方針

**商用リリースのトリガーは「プロダクトの準備完了」ではなく「需要の確認」。**

- 見込み客が1社しかいない状態で月$45の固定費を発生させない
- Stripeゲートはテスターの検証を妨げるので、需要確認前には入れない
- テスターのフィードバックは需要検証と並行して随時対応する

## Phase 1: 需要検証（現在）

> 目的: 「お金を払う人がいるか」を確認する。まだ課金しない。
> 期間: 有料利用の意思表示が3サロン以上になるまで

### 集客戦略: ブログSEO + 紹介特典（運用コスト最小化）

SNSは運用コスト（毎日の投稿・リプ対応）に対して効果が薄いため不採用。
代わりに **作り切りで効果が持続する仕組み** に注力する。

#### SEOブログ（月2本、AI下書き + 5分チェック）
- ターゲットKW: 「エステサロン カルテ管理」「個人サロン 確定申告」「エステ 回数券 管理」等
- 記事生成フロー: Claude API → 下書き生成 → オーナーが5分で確認 → 公開
- 運用コスト: **月10分**（チェック5分 × 2本）
- 効果: 検索流入が積み上がり、放置しても集客し続ける

#### 紹介特典（口コミドリブン）
- テスター・既存ユーザーが知り合いのサロンオーナーを紹介
- **紹介者**: スタンダードプラン1ヶ月無料（2,980円分）
- **被紹介者**: 初月無料でスタンダードプラン体験
- 紹介コード方式（ユーザーごとに固有コードを発行）
- 設定画面に「友だちに紹介する」セクションを追加
- 運用コスト: **ゼロ**（システムが自動処理）

### 1-4 の監視方法

LP経由の新規登録を監視するには以下の2つを組み合わせる:

1. **GA4**: LP → `/signup` へのコンバージョン数を確認（GA4ダッシュボードで「ページ遷移」を見る）
2. **Supabase Auth**: `auth.users` テーブルの新規ユーザー数を定期確認（ダッシュボード → Authentication → Users）

開発で追加対応するなら:
- Supabase の `salons` テーブルの件数を週次で確認するだけでも十分（新規サロン = 新規登録）
- 通知が欲しければ、新規サロン作成時に Resend でオーナー宛にメール通知する仕組みを追加（工数0.5日）
