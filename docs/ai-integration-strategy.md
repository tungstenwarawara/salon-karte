# AI統合戦略 — salon-karte

> 作成日: 2026-03-02
> ステータス: 検討中（未着手）

## 現状

salon-karteはAI機能ゼロの純粋な業務アプリ。21テーブル・23 RPC関数・12 APIルートで
顧客管理・カルテ・予約・在庫・売上分析・LINE連携・Web予約まで一通り揃っている。

## 目的

個人サロンオーナーの「面倒な入力作業」と「判断の迷い」を減らす。
技術的にクールなことではなく、**業務時間の短縮**が唯一の指標。

---

## Stage 1: 入力効率化（MVP）

### 1-1. 音声カルテ入力

**ユースケース**: 施術後にスマホに向かって話すだけでカルテの各フィールドが埋まる

**技術選定（2026-03時点の評価）**:

| 技術 | 日本語精度 | レイテンシ | コスト/分 | API提供 | 備考 |
|------|-----------|-----------|----------|---------|------|
| OpenAI Whisper API | 中〜高（CER未公開） | 低遅延 | $0.006 | あり | 英語67%の学習データ偏り |
| gpt-4o-mini-transcribe | **高**（日本語は強化言語） | 320ms | $0.003 | あり | 2025-12月スナップショットで日本語改善 |
| Kotoba-Whisper | 高（日本語特化） | 高速（6.3x） | セルフホスト | OSS | ReazonSpeechドメインに強い |
| Aqua Voice (Avalon API) | **最高**（99.1%公称） | 450-850ms | 未公開 | あり（OpenAI互換） | 画面コンテキスト認識が強み |
| Deepgram | 高 | 低遅延 | $0.0025〜 | あり | コスト最安 |

**推奨**: `gpt-4o-mini-transcribe` をベースライン採用
- 理由: (1) 日本語が明示的に強化言語 (2) コスト最安クラス ($0.003/分) (3) OpenAI SDK統合が容易 (4) ハルシネーション90%削減（Whisper v2比）
- Aqua Voice Avalon APIは精度最高だが、料金未公開・サロン業務用語での実績が不明

**構成**:
```
[スマホ録音] → Edge Function (gpt-4o-mini-transcribe)
             → Claude Haiku (フィールド分類・構造化)
             → フォームにプリフィル
```

**注意**: 音声→テキスト変換の精度と、テキスト→構造化データの精度は別問題。
サロン固有の用語（施術名・化粧品名）は音声認識側で誤認しやすい。
→ メニューマスタ・商品マスタを用語辞書として構造化ステップに渡す設計が必要。

### 1-2. LINE返信文面の自動生成

**ユースケース**: 予約確認・リマインドの文面を顧客の過去履歴に基づいてパーソナライズ

**構成**:
```
[顧客データ + 予約情報] → Claude Haiku → 文面候補3件 → オーナー選択・編集 → LINE送信
```

**コスト試算**: Haiku 4.5で1件あたり ~$0.001以下（入力500トークン+出力200トークン程度）

## Stage 2: 分析・提案

### 2-1. 来店予測・離脱アラート強化

現在の `get_lapsed_customers` は単純な日数閾値。
→ 過去の来店間隔パターンから「次回来店予測日」を算出し、遅れている顧客を優先表示。

**技術**: Claude Haiku（ルールベース+LLM判定のハイブリッド）
- 統計的な来店間隔の平均・分散はDB側で計算
- 「この顧客は離脱しそうか」の最終判定にLLMを使う（説明文生成も兼ねる）

### 2-2. カルテサマリー・引き継ぎメモ

顧客の過去カルテ全件を要約し、「この顧客に施術する前に知っておくべきこと」を生成。

## 実装タイミングの判断

### 今やるべきか？

**結論: 今ではない。**

**理由**:
1. **コアの安定が先**: Web予約機能がマージされたばかり。まだ実ユーザーからのフィードバックが蓄積していない
2. **需要の検証が未完了**: 音声カルテ入力を「欲しい」と言っているユーザーがいるか？機能リクエストの裏付けがない
3. **LP・集客が未完了**: AI機能より先に、ユーザー獲得の仕組み（LP・料金プラン・決済）を固める方が事業インパクトが大きい
4. **技術の進化速度**: 音声認識APIは半年で大きく変わる。2026年後半にはさらに安く・精度が上がる可能性が高い

### いつやるべきか？

| マイルストーン | やること |
|--------------|---------|
| **今** | この戦略ドキュメントを保存。技術選定の判断材料として維持 |
| **ユーザー10人到達** | 実際の使い方を観察。「カルテ入力が面倒」の声があるか確認 |
| **需要確認後** | Stage 1-1（音声カルテ）のプロトタイプを1週間で作り、テストユーザーに提供 |
| **Stage 1 検証後** | 利用率を見てStage 2に進むか判断 |

## Aqua Voice vs Whisper系 — 正直な評価

### Aqua Voiceの強み
- 日本語精度99.1%（公称）は圧倒的
- 画面コンテキスト認識で専門用語に強い
- 開発者から「認識精度が別次元」と高評価

### salon-karteに採用しない理由（現時点）
1. **エンドユーザー向けツール**: Aqua Voiceはデスクトップアプリ。サロンオーナーはスマホメイン
2. **iOS版は2026年3月リリースしたばかり**: 安定性が未検証
3. **API料金未公開**: SaaS組み込みのコスト計算ができない
4. **ロックイン懸念**: OpenAI互換APIとはいえ、独自機能（コンテキスト認識）に依存すると移行困難

### 推奨アプローチ
- **ベースライン**: gpt-4o-mini-transcribe（日本語強化済み・最安・安定）
- **比較テスト**: 実装時にAqua Voice Avalon APIの料金が公開されていれば並行テスト
- **フォールバック設計**: STT部分を抽象化し、プロバイダー差し替え可能にする
