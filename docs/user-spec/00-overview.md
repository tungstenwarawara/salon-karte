# salon-karte ユーザー仕様書（マニュアル兼テスト基準）

> 更新日: 2026-04-28
> 目的: サロンオーナー（ユーザー）が「どの画面で何をすると何が起きるか」を**漏れなく**把握できるマニュアル。同時に、ドッグフーディング・人力テスト・E2E テストの基準としても使う。

---

## このドキュメントの位置づけ

| 観点 | このドキュメント | `user-flow-diagrams.md`（既存） |
|------|----------------|------------------------------|
| 目的 | 各画面の操作詳細・条件分岐 | 画面遷移・業務フロー・データフローの俯瞰 |
| 粒度 | マニュアル粒度（ボタン1つ単位） | 鳥瞰図（Mermaid 中心） |
| 用途 | ドッグフーディング・テストケース作成・営業デモ | 全体像の把握・新規導線の設計 |

**両方を併存**させる。重複は出さない方針なので、画面遷移図は `user-flow-diagrams.md` を参照、各画面の詳細は本ドキュメントを参照する。

---

## 対象読者

1. **サロンオーナー（ユーザー）**: 操作に困ったときに該当ファイルを開けば手順が書いてある状態
2. **テスター**: 各操作・条件分岐に対して期待動作が明示されている → 不具合検出の基準として使える
3. **開発者・Claude**: 仕様確定済みの動作を変更しないための回帰防止リファレンス

## 各ファイルの記法

### 章構成

```markdown
# 領域名

> 一言サマリー（このファイルで扱う画面・機能）

## 画面1の名前（URL）

### 画面イメージ
（スクショ）

### このページに来るシチュエーション
（オーナーが何をしたくてこの画面に来るか）

### 画面の構成（番号付き）
1. **位置**: 要素名 — 説明
...

### こんなときどうする？
| やりたいこと | 操作 |
| --- | --- |

### 状態別の見え方
（通常 / 空 / 検索0件 / エラー / 読み込み中 / 認証エラー など）

### 操作と結果
| 操作 | 結果 |
| --- | --- |

### バリデーション
| 項目 | 必須 | 形式 | エラーメッセージ |
| --- | --- | --- | --- |

### 注意事項・今後の予定
（実装済み機能のうち分かりにくい挙動 / 未実装機能の TODO）
```

### スクショの差し込み

各画面の冒頭に `![画面名](./screenshots/{ファイル名}.png)` を**先に書いておく**。画像ファイルは Phase 2 で Playwright スクリプトで一括生成する。今は画像が無くてもマークダウンとしては有効。

### スクショファイルの命名規則

```
{ファイル番号 2桁}-{領域名}-{画面名}[-{状態}].png
```

| 例 | 説明 |
|----|------|
| `04-customers-list.png` | 顧客一覧 通常状態 |
| `04-customers-list-empty.png` | 顧客一覧 空状態 |
| `04-customers-list-no-results.png` | 顧客一覧 検索結果0件 |
| `04-customers-new.png` | 顧客 新規登録 空フォーム |
| `04-customers-new-collapsed-open.png` | 顧客 新規登録 詳細情報を展開 |
| `04-customers-detail.png` | 顧客詳細 通常状態 |
| `04-customers-edit.png` | 顧客 編集 |
| `04-customers-edit-delete-confirm.png` | 顧客 編集 削除確認パネル展開 |
| `06-appointments-calendar.png` | 予約カレンダー |
| `15-public-booking-step1.png` | Web 予約 メニュー選択 |

### 撮影想定環境

| 項目 | 値 |
|------|-----|
| ビューポート | 375px × 812px（iPhone SE / 13 mini 想定） |
| ログインアカウント | テストサロン花（`test-salon@salonkarte.com`） |
| データ | `npx tsx scripts/seed-test-data.ts` で投入したテストデータ |
| 撮影タイミング | 描画完了 + アニメーション収束後（Playwright `waitForLoadState("networkidle")` 相当） |

### 「実装済み」と「今後の予定」の書き分け

| 表記 | 意味 |
|------|-----|
| そのまま記述 | 実装済み・現行動作 |
| `> 注意:` | 実装済みだが分かりにくい挙動・落とし穴 |
| `> 今後の予定:` | 未実装。Phase 2 以降で対応予定 |
| `> 既知の問題:` | バグ・テスターから報告された不具合 |

## 操作と結果の記法ルール

### 「操作」の書き方

- **クリック**: 「`保存する` ボタンを押す」
- **入力**: 「メールアドレス欄に `〜` と入力する」
- **選択**: 「婚姻状況のドロップダウンで `既婚` を選ぶ」
- **遷移**: 「`+ 顧客を登録` を押す」（結果は「結果」列に）

### 「結果」の書き方

| パターン | 書き方の例 |
|---------|----------|
| 画面遷移 | `/customers/{id}` に遷移する |
| Toast 通知 | 画面上部に「顧客を登録しました」と表示される |
| エラー表示 | 画面上部に赤い ErrorAlert で「登録に失敗しました: {実際のエラーメッセージ}」と表示される |
| 状態変化 | ボタンが `保存中...` に変わり、押せなくなる |
| データ変化 | DB の `customers` テーブルに 1 行追加される |

## バリデーションの書き方

```markdown
| 項目 | 必須 | 形式 | エラー時の挙動 |
| --- | --- | --- | --- |
| 姓 | ✅ | 文字列 | HTML5 `required` で「このフィールドを入力してください」 |
| 電話番号 | ❌ | 任意の文字列（書式チェックなし） | — |
| 身長 (cm) | ❌ | 数値（小数1位まで） | parseFloat で NaN なら null として保存 |
```

## メンテナンス方針

1. 実装変更があったら、該当ファイルを更新する
2. スクショは UI 変更時に Playwright スクリプトで再生成（Phase 2 以降）
3. 「今後の予定」の項目は実装完了次第「実装済み」に書き換える
4. 各ファイルの冒頭に `更新日` を入れる。古い記述は信用しない方針

> **静的な進捗表は記載しない**（陳腐化するため）。各ファイルは「現時点のスナップショット」として、必要に応じて実測で再確認する。
