## 顧客一覧（/customers）

### 画面イメージ

![顧客一覧 通常](./screenshots/04-customers-list.png)

### このページに来るシチュエーション

- 既存のお客様を探したい / 詳細を見たい
- 新しいお客様を登録したい
- 来店間隔が空いているお客様を確認したい

### 画面の構成

1. **ヘッダー左**: タイトル「顧客一覧」+ 件数表示（フィルタ後 / 全体）
2. **ヘッダー右**: 「+ 顧客を登録」ボタン → `/customers/new` へ遷移
3. **検索ボックス**: 名前・カナ・電話番号で部分一致検索（リアルタイム）。入力時はクリアボタン (×) が右端に出る
4. **来店間隔フィルタ（横スクロール）**: `全員` / `30日+` / `60日+` / `90日+` のピル型ボタン
5. **ソート**: `カナ順` / `来店日` / `回数` のセグメンテッドコントロール
6. **卒業除外トグル**（卒業済み顧客が1人以上いるときのみ表示）: 押すと卒業済みを含めた一覧になる
7. **顧客カード**: 1人につき1カード。氏名 + カナ + 来店回数 + 最終来店経過日
8. **「もっと見る」ボタン**: 20件以上のときに残件数とともに表示

### こんなときどうする？

| やりたいこと | 操作 |
| --- | --- |
| 新しいお客様を登録 | 右上の `+ 顧客を登録` を押す |
| お客様を名前で探す | 検索ボックスに名前 / カナ / 電話番号の一部を入力 |
| 60日以上来ていないお客様を一覧表示 | 来店間隔フィルタの `60日+` を押す |
| 来店日が新しい順に並べる | ソートの `来店日` を選ぶ |
| 顧客詳細を開く | 顧客カードを押す → `/customers/{id}` へ遷移 |
| 卒業にしたお客様も表示 | 右上の `卒業 N` ボタンを押す（N = 卒業件数） |

### 状態別の見え方

#### 顧客が1人も登録されていないとき
- 顧客カード一覧の代わりに「顧客が登録されていません」のEmptyStateが表示される
- 「最初のお客様を登録する →」リンクから `/customers/new` へ
- 検索・フィルタ・ソート・卒業ボタンは表示されたまま（操作しても変化なし）

#### 検索またはフィルタの結果が0件のとき
- 「該当する顧客が見つかりません」と表示
- 件数表示は `0/全件名` の形式

#### 初回訪問時
- ページ上部に FirstVisitHint で「まずはお客様を登録しましょう。登録後、予約やカルテの記録ができるようになります」が表示される（20秒で自動フェードアウト、または閉じるボタンで非表示）

#### 来店経過日数による顧客カードの色分け
| 最終来店経過 | 表示色 |
|------------|------|
| 30〜59日 | 黄色 |
| 60〜89日 | 橙色 |
| 90日以上 | 赤色 |
| 30日未満 | 経過日表示なし（来店日のみ） |
| 未来店 | グレーで「未来店」表示 |

#### 卒業済み顧客のカード
- 氏名の右に橙色で「卒業」のラベルが付く
- デフォルトでは一覧に表示されない（`hideGraduated` トグルで切替）

### 操作と結果

| 操作 | 結果 |
| --- | --- |
| 検索ボックスに入力 | リアルタイムで一覧が絞り込まれる + ページネーションが先頭に戻る |
| 検索クリア (×) を押す | 検索が解除される |
| 来店間隔フィルタを切替 | フィルタ適用 + ページネーションが先頭に戻る |
| ソートを切替 | 並び順が変わる（ページネーションは維持） |
| 卒業除外トグルを押す | 卒業済みの表示/非表示が切替 |
| 顧客カードを押す | `/customers/{id}` に遷移 |
| 「もっと見る」を押す | 表示件数が +20 件される |

> 注意: 検索・フィルタ・ソートはクライアント側で全件処理する。顧客が数千人になると重くなる可能性がある（現在は 50人までの想定）。

## 顧客 新規登録（/customers/new）

### 画面イメージ

![顧客 新規登録 空フォーム](./screenshots/04-customers-new.png)

![顧客 新規登録 詳細情報を展開](./screenshots/04-customers-new-collapsed-open.png)

### このページに来るシチュエーション

- 新しいお客様の情報を登録したい
- 来店前の事前情報（電話・アレルギー・施術目標等）を残したい

### 画面の構成

1. **PageHeader**: タイトル「顧客を追加」+ パンくず `顧客一覧 > 新規登録`
2. **下書き復元バナー**（条件付き）: 過去の入力途中データがあれば「前回の入力内容を復元しました」が表示される。`閉じる`ボタンで非表示
3. **基本情報セクション**: 姓・名（必須）、セイ・メイ、生年月日、電話番号、メールアドレス、住所
4. **詳細情報セクション**（折りたたみ）: クリックで展開
   - 属性情報: 婚姻状況 / お子様の有無 / DM送付（既定: 可）
   - 施術関連情報: 身長・体重・アレルギー・施術の最終目標・メモ
5. **送信エリア**: 左に `キャンセル` ボタン、右に `保存する` ボタン

### こんなときどうする？

| やりたいこと | 操作 |
| --- | --- |
| 必要最低限だけ登録（姓・名のみ） | 姓と名を入力して `保存する` を押す |
| 詳細情報も登録 | 「詳細情報を追加（任意）」を押して展開 → 入力 |
| 入力途中で他のページに移動 | 自動で下書きが localStorage に保存される。次回フォームを開くと復元バナーが出る |
| 登録をやめる | 左下の `キャンセル` を押す → 直前のページに戻る |

### 状態別の見え方

#### 通常時
- 姓・名の右に赤い `*` で必須マーク
- プレースホルダー例: 姓=「山田」、名=「花子」、電話=「090-1234-5678」など
- DM送付の既定値は `可`

#### 下書き復元時
- 入力欄に前回の値が事前入力された状態で表示
- 上部にアクセントカラーのバナーが表示される

#### 保存中
- `保存する` ボタンが `保存中...` に変わり、押せなくなる（二重送信防止）

#### 保存失敗時
- フォーム上部に赤い ErrorAlert で「登録に失敗しました: {実際のエラーメッセージ}」と表示
- ボタンは元の状態に戻り、再送信できる

### 操作と結果

| 操作 | 結果 |
| --- | --- |
| 姓・名を空のまま `保存する` | HTML5 標準のバリデーションで「このフィールドを入力してください」 |
| 必須項目を入力して `保存する` | DB に新規レコード作成 → 下書きクリア → Toast「顧客を登録しました」→ `/customers/{id}` に遷移 |
| `キャンセル` を押す | `router.back()` で直前のページに戻る（下書きは保持される） |
| 詳細情報を展開してから閉じる | 展開時に入力した値は保持される |

### 入力フィールドの仕様

| 項目 | 必須 | 形式・備考 |
| --- | --- | --- |
| 姓 | ✅ | 文字列 |
| 名 | ✅ | 文字列 |
| セイ・メイ | ❌ | 文字列。検索インデックスに使用されるので入力推奨 |
| 生年月日 | ❌ | `<input type="date">`（YYYY-MM-DD） |
| 電話番号 | ❌ | `<input type="tel">`。書式チェックなし |
| メールアドレス | ❌ | `<input type="email">`。書式不正なら HTML5 バリデーション |
| 住所 | ❌ | 文字列 |
| 婚姻状況 | ❌ | `未婚` / `既婚` / 未選択 |
| お子様 | ❌ | `あり` / `なし` / 未選択 |
| DM送付 | ❌ | `可`（既定）/ `不可` |
| 身長 (cm) | ❌ | 数値（小数1位まで）。数値以外は null として保存 |
| 体重 (kg) | ❌ | 数値（小数1位まで）。同上 |
| アレルギー・注意事項 | ❌ | 自動リサイズ複数行入力 |
| 施術の最終目標 | ❌ | 自動リサイズ複数行入力 |
| メモ | ❌ | 自動リサイズ複数行入力 |

> 注意: 任意項目で空文字のまま保存した場合、DB には null で保存される（空文字としては保存しない）。

## 顧客詳細（/customers/[id]）

### 画面イメージ

![顧客詳細](./screenshots/04-customers-detail.png)

### このページに来るシチュエーション

- 来店中のお客様のカルテ・カウンセリング・回数券残数を確認したい
- 過去の購入履歴・施術メニュー傾向を見たい
- 編集・卒業・物販登録・回数券登録などのアクションを起こしたい

### 画面の構成（上から順に）

1. **PageHeader**: タイトル「{姓} {名}」+ パンくず `顧客一覧 > {姓} {名}` + 右側に `編集` リンク（`/customers/{id}/edit` へ）
2. **氏名カナ**（カナがあれば）: PageHeader 直下に小さく表示
3. **来店分析セクション**: 来店回数 / 最終来店経過日 / 平均来店間隔 の 3カラムの数値表示
   - 60日以上未来店なら橙色アラート、90日以上なら赤色アラートを表示
   - 未来の予約があれば青色枠で日時とメニューを表示
   - 予約がなく来店履歴がある場合のみ「次回予約を登録する」リンクを表示
4. **顧客インサイトセクション**（データがあれば）: よく選ぶメニュー Top3 / よく買う商品 Top3 / 累計売上サマリー（施術・物販・回数券・合計）
   - すべてゼロの場合はセクション自体が非表示
5. **基本情報セクション**: 電話 / メール / 生年月日（年齢併記） / 住所 / 婚姻状況 / お子様 / DM送付
   - 電話番号タップ → 端末の電話アプリ起動（`tel:` リンク）
   - メールアドレスタップ → 端末のメールアプリ起動（`mailto:` リンク）
   - 未登録項目は「未登録 →」のリンクで `/customers/{id}/edit` に飛べる
6. **施術関連情報セクション**: 身長 / 体重 / アレルギー / 最終目標 / メモ（登録があるもののみ表示）
7. **卒業トグル**: 通常時は「卒業にする」のテキストリンク。卒業済みなら橙色枠で「卒業済み + 卒業日 + 復帰する」表示
8. **LINE連携セクション**: 紐付け済みなら表示名と紐付け解除ボタン、未紐付けなら友だち選択UI
9. **タブ切替セクション**: `施術` / `写真` / `回数券` / `物販` / `カウンセリング` のタブ。各タブの数字バッジ付き
   - 写真タブは写真が1枚以上あるときのみ表示
   - 各タブ内の詳細仕様は別ファイルへ:
     - 施術 → `05-records.md`
     - 写真 → `05-records.md`（カルテに紐づくため）
     - 回数券 → `09-tickets.md`
     - 物販 → `08-products.md`
     - カウンセリング → `10-counseling.md`

### こんなときどうする？

| やりたいこと | 操作 |
| --- | --- |
| 顧客情報を編集 | PageHeader 右の `編集` を押す |
| 電話をかける | 基本情報の電話番号をタップ |
| 次回予約を登録 | 来店分析セクションの「次回予約を登録する」リンク（来店履歴があるときのみ表示） |
| 過去のカルテを見る | 施術タブを開く |
| 回数券残数を確認 | 回数券タブを開く |
| LINE友だちと紐付け | LINE連携セクションの「LINE友だちを紐付ける」を押す（事前に LINE連携設定が必要） |
| 卒業（来店終了）扱いにする | 「卒業にする」を押す → 確認パネル → `卒業にする` を押す |

### 状態別の見え方

#### 来店履歴ゼロのお客様
- 来店回数 `0`、最終来店「未来店」、平均間隔「-」
- 顧客インサイトセクションは非表示
- 「次回予約を登録する」リンクは表示されない（来店履歴がないため）

#### 60〜89日未来店
- 来店分析セクションに橙色枠で「60日以上ご来店がありません。」と表示

#### 90日以上未来店
- 同枠が赤色になり「90日以上ご来店がありません。フォローの連絡をおすすめします。」

#### 卒業済み
- 卒業トグルが「卒業済み + 卒業日 + 復帰する」のラベル表示
- 一覧画面ではデフォルト非表示（顧客一覧 参照）

#### LINE連携の状態別表示
| 状態 | 表示 |
|------|-----|
| 紐付け済み・友だち追加中 | 緑色のドット + 表示名 + `解除` ボタン + 紐付け日 |
| 紐付け済み・ブロック中 | グレーのドット + 表示名 + `（ブロック中）` |
| 未紐付け・未紐付け友だちあり | `未紐付け` 表示 + `LINE友だちを紐付ける` ボタン |
| 未紐付け・未紐付け友だちなし | `未連携` 表示 + `LINE連携設定` への案内リンク |

#### 顧客が存在しない（不正なIDをURL指定）
- Next.js の `notFound()` により 404 ページが表示される
- 別サロンの顧客ID を指定した場合も 404（salon_id でフィルタされるため）

### 操作と結果

| 操作 | 結果 |
| --- | --- |
| `編集` を押す | `/customers/{id}/edit` に遷移 |
| 電話番号をタップ | 端末の電話アプリが起動 |
| メールをタップ | 端末のメールアプリが起動 |
| 「卒業にする」→ 確認 → `卒業にする` | `customers.graduated_at` が現在時刻に更新 → 画面リフレッシュ |
| 卒業済み顧客で `復帰する` | `customers.graduated_at` が null に更新 → 画面リフレッシュ |
| LINE友だちを選択して `紐付け` | `customer_line_links.customer_id` が更新 → セクション内表示が紐付け済みに変化 |
| LINE紐付け済みで `解除` | `customer_line_links.customer_id` が null に → 未紐付けセクションに変化 |
| 各タブを切替 | 表示が切り替わる（State は保持されるので、回数券操作中などの作業状態が消えない） |

## 顧客 編集（/customers/[id]/edit）

### 画面イメージ

![顧客 編集](./screenshots/04-customers-edit.png)

![顧客 削除確認](./screenshots/04-customers-edit-delete-confirm.png)

### このページに来るシチュエーション

- 既存のお客様情報を変更したい（誤入力修正・電話番号変更等）
- 詳細情報（属性・施術関連情報）を後から追記したい
- 重複登録などで顧客を削除したい

### 画面の構成

1. **PageHeader**: タイトル「顧客情報を編集」+ パンくず `顧客一覧 > {姓} {名} > 編集`
2. **基本情報セクション**: 新規登録と同じフィールド（既存値が事前入力された状態）
3. **属性情報セクション**: 婚姻状況 / お子様 / DM送付（折りたたみではなく常時展開）
4. **施術関連情報セクション**: 身長 / 体重 / アレルギー / 最終目標 / メモ（常時展開）
5. **送信エリア**: `キャンセル` / `保存する`
6. **危険な操作セクション**（赤い枠）: 「この顧客を削除」ボタン

### こんなときどうする？

| やりたいこと | 操作 |
| --- | --- |
| 情報を編集 | 該当フィールドを修正して `保存する` |
| 編集をキャンセル | `キャンセル` を押す → 直前のページに戻る |
| 顧客を削除 | 下部の `この顧客を削除` を押す → 赤い確認パネルで `削除する` を押す |

### 状態別の見え方

#### 通常時
- 既存値がすべての入力欄に反映済み
- 削除セクションは下部に常に表示（折りたたまれていない）

#### 削除確認パネル
- 赤色枠で「この顧客を削除しますか？」と表示
- 補足: 「顧客情報と関連する全ての施術記録・写真が削除されます。この操作は取り消せません。」
- `キャンセル` / `削除する` の 2 ボタン

#### 保存中
- `保存する` ボタンが `保存中...` に変わり、押せなくなる

#### 削除中
- `削除する` ボタンが `削除中...` に変わり、押せなくなる

#### 保存・削除失敗時
- フォーム上部に赤い ErrorAlert で「更新に失敗しました: {エラー}」または「削除に失敗しました: {エラー}」を表示

### 操作と結果

| 操作 | 結果 |
| --- | --- |
| 入力を変更して `保存する` | DB の `customers` テーブルが更新 → Toast「顧客情報を更新しました」→ `/customers/{id}` に戻る |
| `キャンセル` を押す | `router.back()` で直前のページへ |
| `この顧客を削除` を押す | 削除確認パネルが展開（まだ削除されない） |
| 削除確認パネルの `キャンセル` を押す | パネルが閉じる |
| 削除確認パネルの `削除する` を押す | 関連するカルテ写真をストレージから削除 → DB の顧客レコードを削除 → Toast「顧客を削除しました」→ `/customers` に戻る |

### 削除時のデータ影響範囲

> **重要**: 顧客を削除すると、関連する以下のデータも DB の外部キー制約 (CASCADE) により削除される:
> - 施術カルテ（`treatment_records`）
> - 施術メニュー履歴（`treatment_record_menus`）
> - 物販履歴（`purchases`）
> - 回数券（`course_tickets`）
> - 予約（`appointments`）
> - カウンセリングシート（`counseling_sheets`）
> - LINE連携リンク（`customer_line_links` の customer_id が null になる）
> - 施術写真ファイル（Supabase Storage の `treatment-photos` バケットからも削除）

> 注意: 削除は元に戻せない。誤削除を防ぎたい場合は「卒業にする」（顧客詳細ページ）の利用を案内するのが適切。

## 共通: バリデーション

新規登録・編集の両画面で同じバリデーションが適用される。

### 必須項目

| 項目 | バリデーション | エラー時の挙動 |
| --- | --- | --- |
| 姓 | HTML5 `required` | 「このフィールドを入力してください」（ブラウザ標準） |
| 名 | HTML5 `required` | 同上 |

### 形式チェック

| 項目 | 入力タイプ | 補足 |
| --- | --- | --- |
| メールアドレス | `<input type="email">` | 書式不正なら HTML5 標準のバリデーション |
| 電話番号 | `<input type="tel">` | 書式チェックはしない（「-」あり/なし両方OK、ハイフン任意） |
| 生年月日 | `<input type="date">` | YYYY-MM-DD のみ受け付け |
| 身長 (cm) | `<input type="number" step="0.1">` | 数値以外は null |
| 体重 (kg) | `<input type="number" step="0.1">` | 同上 |

### 認証・権限

| 状態 | 挙動 |
| --- | --- |
| 未ログイン | `/login` へリダイレクト |
| ログイン済み・サロン未作成 | `/setup` へリダイレクト |
| 別サロンの顧客IDを URL に指定 | 404（salon_id フィルタにより該当データが取れないため） |

### サロン分離（マルチテナント）

すべての顧客クエリ・更新には `.eq("salon_id", salon.id)` が必須付与されている。これにより、自サロン以外の顧客には絶対にアクセスできない（コード側 + RLS の二重防御）。

## 既知の問題・今後の予定

### 既知の問題

- 一覧画面の検索・フィルタ・ソートはクライアント側で全件処理する。顧客が数千人になると体感が重くなる可能性
- 検索の精度は単純な部分一致のみ（ローマ字・あいまい検索なし）
- DM 送付不可の顧客に対する一括送信ガード機能はまだない（手動運用が前提）

### 今後の予定（実装予定 / 未実装）

| 項目 | 状態 | 優先度 |
| --- | --- | --- |
| Free プランの顧客数上限（50人）チェック | 未実装。Phase 2 で `<FeatureGate>` 経由で実装予定 | 高 |
| 顧客一括 CSV インポート | 別画面で部分実装あり（`/settings/import-customers`） → `14-settings.md` 参照 | 中 |
| 顧客一覧の CSV エクスポート | `/settings/export` に部分実装あり → `14-settings.md` 参照 | 中 |
| 顧客カードに次回予約日を表示 | 未実装。来店分析セクションには表示済みだが、一覧での視認性は低い | 低 |
| 顧客タグ機能（任意ラベル付け） | 未実装。テスターからの要望次第 | 低 |
| カナのあいまい検索（ひらがな⇔カタカナ） | 未実装 | 低 |

### Phase 2 で必須対応

- **顧客数上限ゲート**: Free プランは 50人で登録ブロック → アップグレード案内のモーダル表示
  - 実装場所: `/customers/new` の Submit ハンドラ + 一覧画面の `+ 顧客を登録` ボタン
  - 仕様詳細は `13-billing.md` に記載予定
